# MOEX margined options

```
python examples/moex_options/run_all.py
python examples/moex_options/run_all.py --only m01
```

Needs `GRPC_TOKEN` and `GRPC_SERVER_URL` in the repository's `.env`: **the underlying here is
real**.

---

## What is real and what is not

| | source |
|---|---|
| SBER daily bars | **real**, your gRPC feed |
| contract conventions | **measured** against the feed's reference service |
| codes such as `SR310CI6` | **checked** against the feed; the round trip closes |
| the expiry calendar | **measured**: third Wednesday, plus weeklies |
| **option prices** | **generated by a model** |

OPRA option quotes are closed by your token's entitlements (`PERMISSION_DENIED` on candles while
the reference service answers), and the feed lists no expired series on any market — so the chain
is synthetic. No number here describes a return, and the report does not print one: `summarise`
calls `refuse_performance_claims`, and the table has no return column.

A note on entitlements: quotes for **Russian** options are available (`SBER` → `SR300CU6` → 15
daily candles). So m01 and m02 can be moved onto real prices if wanted — but only forward, on live
series, because the feed does not serve expired ones.

## How this differs from `examples/options` (SPY)

Not in presentation. The same instrument on two venues is two different sets of books:

| | OPRA (SPY) | MOEX (SBER) |
|---|---|---|
| premium | paid at the trade | **not paid**; variation margin |
| position value | `price × 100 × quantity` | **zero** — the P&L is already in cash |
| initial margin | none | **on both sides** |
| exercise | AMERICAN | EUROPEAN |
| settlement | PHYSICAL | CASH |
| expiries | **every session** | third Wednesday of the month |
| code | `SPY   260914C00765000` | `SR310CI6` |

A run shows it directly: `portfolio value == cash` on every session, and the cash changes every
day without a single trade. That is the variation margin. A premium-paid option would do the
opposite — the cash sits still and the position value floats.

All of it is selected by one word: `venue=MOEX` in `SyntheticOptionChainSource`, where `MOEX` is
the venue this package registers with ziplime through `register_venue`.

## The strategies

| file | what it shows |
|---|---|
| `m01_margined_vertical.py` | A short call spread held to expiry. Sized **off the maximum loss and the margin** rather than off a credit received — there is none. Settled at intrinsic value on expiry. |
| `m02_margin_managed_strangle.py` | A short strangle whose exit is **margin usage** rather than loss. What forces a margined position out is the collateral. |

The second deserves saying plainly: in a run it **overshoots** its own threshold. The threshold is
25%, and actual usage reached 67%, 87% and 108% — that is, the collateral once consumed the whole
account. Halving the position once a session cannot keep up with the margin growing when the
underlying walks into the strike. That is not a flaw in the example, it is the content of it: a
short strangle outruns its risk management, and on a margined market that ends in a margin call
rather than in a drawdown.

## Three limits worth knowing before building on this

**Monthly series only.** Weeklies exist, but their code carries a week suffix whose rule does not
follow from the data: measured, 2026-09-16 is `SR300CI6`, 2026-09-23 is `SR300CI6D`, and
2026-09-30 is already `SR300CJ6A`, with October's month letter. Generating them by guesswork
produces three series under one name; `format_moex_symbol` refuses to do it, and the asset
repository refuses to store different contracts under one name.

**The contract size does not come from the data.** The feed reports `multiplier = 0` and
`contract_size = 1` for every MOEX option; both are placeholders. A SBER put at 16.59 against an
underlying of 283 is quoted per share, and the contract covers an SBRF future — a hundred shares.
The venue preset carries 100, from the contract specification rather than from the feed. For any
root other than SBER this is worth rechecking.

**Nor does the margining.** The API reports `settlement_type = CASH` and `style = EUROPEAN`, but
"the premium is not paid up front" is not expressed in the schema at all. `PremiumStyle.MARGINED`
is set in the preset from knowledge of the market. If that is not true for some contract, it is
one line to change.

**There are no intraday runs here.** A real MOEX option prints 23-54 minute bars in a session
rather than five hundred, and FORTS trades until 23:50 while the `XMOS` calendar in
`exchange_calendars` ends the session at 18:45 — an intraday run would quietly lose the evening
session.
